# 🛠️ 工作總結：LLM Training Platform

> **摘要**：本文件總結了 LLM 訓練平台的架構與核心專案經驗。作為 Internal Tool Team，我們致力於提升 7,000+ GPU 的運維效率與穩定性。

## 一、平台概述 (Overview)

我們是一個 **LLM Training Platform**，管理著分布在不同 AWS EKS Cluster 上的 **7,000+ GPU**。
[cite_start]作為 Internal Tool Team，我們負責處理 Health Check、Node Remediation 等運維工作，主要服務對象是 Scientists (科學家/研究人員) [cite: 3]。

---

## 二、系統組件 (System Architecture)

### [cite_start]1. Infrastructure Layer (基礎設施層) [cite: 5]

使用 **AWS EKS Clusters** 託管各種訓練任務，配套存儲系統包括：

* [cite_start]**FSX**: 高吞吐量文件系統，用於訓練過程中的數據訪問 [cite: 7]
* [cite_start]**S3**: 最終的訓練/微調數據存儲系統 [cite: 8]
* [cite_start]**AWS EFA**: 高吞吐量分佈式網絡基礎設施 [cite: 9]

### [cite_start]2. Orchestration Layer (編排層) [cite: 10]

* [cite_start]**Airflow DAGs**: 控制各種預定義的工作流，執行 Health Check、Divergence Test、Node Remediations 等自動化運維任務 [cite: 11]。

### [cite_start]3. RESTful APIs (API 服務層) [cite: 12]

使用 **Lambda + API Gateway** 提供多種服務：

* [cite_start]供 **Airflow** 調用獲取 Cluster Info、NodePool Info (存儲於 SQL) [cite: 14]
* [cite_start]供**客戶**通過 CLI 執行任務或獲取 Job 信息 [cite: 15]

### [cite_start]4. Persistent Layer (持久化層) [cite: 17]

使用關聯式資料庫 (Relational Database) 存儲系統信息：

* [cite_start]🗂️ **Job Table**: 存儲客戶提交的作業詳情 [cite: 19]
* [cite_start]🏃 **Run Table**: 記錄每個作業的運行實例，包含訓練/微調使用的節點 ID [cite: 20]
* [cite_start]📦 **Project/NodePool Table**: 用於命名空間隔離和資源管理 [cite: 21]
* [cite_start]🌐 **Cluster Table**: 維護集群與 Endpoint 的映射關係 [cite: 22]
* [cite_start]🖥️ **Node Table**: 記錄 GPU 序列號、地區、時間戳歷史和節點狀態信息 [cite: 23]

### [cite_start]5. CLI (客戶端接口) [cite: 24]

* [cite_start]將 Lambda 函數封裝為 CLI 工具，提供給客戶使用 [cite: 25]。

### [cite_start]6. CI/CD [cite: 26]

* [cite_start]使用 **Argo Workflow** + **Helm Charts** (依賴模板) 管理所有 EKS 集群的部署和配置 [cite: 27]。
